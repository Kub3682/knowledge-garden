# 第七篇 · 回答之后，怎样查证？

牧人没问系统再猜一遍。他要查的是，A07 究竟被哪一处读到了，能不能从录像里核对。

系统可以调用几个工具。一个查各栏耳标记录，一个查正式转栏单，一个按时刻找录像。工具返回结果之后，再决定下一步。读者可以按顺序展开这三张记录。

## 查到什么，再决定做什么

<details class="reading-note evidence">
<summary>查其他羊栏的耳标</summary>

乙栏在 17:42 读到一次 A07。终端只能说明当时读到了这个耳标。下一步查是否有一张允许它转栏的单子。

</details>

<details class="reading-note evidence">
<summary>查当天的转栏单</summary>

当天没有登记 A07 转去乙栏。记录间有了冲突。系统据此调取乙栏 17:42 附近的录像。

</details>

<details class="reading-note evidence">
<summary>对照录像并交给人核对</summary>

录像显示一只羊在那时进入乙栏，耳标却被挡住。系统报告「乙栏曾读到 A07，建议先去乙栏核实」，留下记录和片段。牧人到乙栏看了耳标，确认 A07 在那里，再把它带回甲栏。

</details>

这项任务要一直保存查到了什么、还缺什么，以及下一步有没有依据。第二篇的代班人要记下「哪张纸已经处理」，这里的系统也要记下「哪个来源已经核对」。**只是现在，下一步会随新证据改变。**

## 什么时候应该停？

查找记录，可以明确允许哪些工具和数据。自动补一张转栏单，会改变账本，还需要知道事实和谁有权确认。录像无法单独辨明耳标时，系统把能够核实的线索交给牧人，这次查证就可以结束。

| 说法 | 怎样核实 |
| --- | --- |
| 「我打算查乙栏。」 | 这是计划 |
| 「乙栏 17:42 读到 A07。」 | 看工具返回的记录 |
| 「A07 已安全回到甲栏。」 | 看实际归栏的后续确认 |

系统帮人找到 A07。可羊仍是牧人亲手带回的。人们接着想，能不能把引导归栏、开门关门中的一部分也交给机器？
