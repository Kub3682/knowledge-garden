# 第三篇 · 怎样让一台机器换题？

甲栏每天五点核对，乙栏六点核对。他们先把时间写成可调整的参数。到了晚些时候，两位牧人想把栏里的 2 只与 3 只合计起来。第二天，他们又想查第一栏和第二栏相差几只。这回改变的是要做的运算。

| 想改什么 | 要换什么 |
| --- | --- |
| 五点核对改成六点 | 时间参数 |
| 第一栏从 2 只变成 4 只 | 输入数据 |
| 合计改成第一栏减第二栏 | 程序中的操作 |

## 操作也能记下来

做一台小教学机。它有一块存储器，每格用地址编号。地址 4 放 2，地址 5 放 3，地址 6 留给结果。机器内部还有一个临时存放数值的位置，叫累加器，简称 ACC。

| 按顺序执行 | 这一步会发生什么 |
| --- | --- |
| `LOAD 4` | 读地址 4，把里面的 2 放入 ACC |
| `ADD 5` | 读地址 5，把里面的 3 加到 ACC |
| `STORE 6` | 把 ACC 中的 5 写进地址 6 |
| `HALT` | 停机 |

**地址告诉机器去哪里取，数值才是取回来计算的东西。** 把第二行换成 `SUB 5` 后，机器会保存 −1，表示第一栏比第二栏少一只。

怎么让机器识别这些指令？我们约定用 104 表示 `LOAD 4`，205 表示 `ADD 5`，305 表示 `SUB 5`。在这套教学编码中，百位说明做什么，后两位给出地址。真正的电子计算机通常用二进制位串保存这些内容。

## 谁来读，谁来算？

把四条已编码的指令也放进存储器，让机器从地址 0 开始。**存储程序**让步骤可以像数据一样保存和更换。某一存储内容被当作指令还是数值，要看机器怎样读取它。

中间有三个值得观察的状态。PC 保存取指的位置，IR 保存已取出的编码，ACC 保存暂存数值。CPU 取出编码、识别操作、执行并保存结果。每点击一次，下图推进其中一步。

先用求和观察从地址 5 取出 3，再看最终结果怎样写进地址 6。切换到求差时，地址 1 的 205 变成 305。**变的只有一条程序指令，计算结果从 5 变成 −1。**

这里的四步用于观察因果。现实中，处理器可以让多条指令的工作重叠。要反复核对多条记录，还能由条件跳转改变取指位置，例如有记录就回到读取的步骤，读完再停机。

## 人怎样写，机器怎样认？

人可以写「把两个羊栏的数量相加」。在高级语言中把这层意思写成明确表达式，编译器就能把它转换成目标机器可用的指令。指令集架构（ISA）规定这些指令怎么编码、会怎样改变可见的机器状态。不同处理器可以用自己的电路实现同一套约定。

**程序把规则写成表示，CPU 把规则落实为状态变化。** 当羊栏越来越多，程序已经能算，接着要问的是，数据怎样整理，哪部分可以一起算？
